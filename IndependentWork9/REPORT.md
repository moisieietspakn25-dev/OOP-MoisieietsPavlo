# Звіт — самостійна робота №9

## 1. Мета
Дослідити застосування `Dictionary<TKey,TValue>` і `HashSet<T>` та реалізувати практичні сценарії їх використання.

## 2. Приклади у відкритих проєктах

### Приклад 1 — Dictionary: Dapper
У документації Dapper показано передавання `Dictionary<string, object>` як набору SQL-параметрів. Словник доречний, оскільки кожен параметр має ім'я (ключ) і значення; пошук параметра за ключем у середньому O(1). Для такого доступу List потребував би послідовного пошуку O(n).
Джерело: https://github.com/DapperLib/Dapper (README містить приклад словника параметрів).

### Приклад 2 — HashSet: .NET Runtime
У вихідному коді .NET Runtime клас `HashSet<T>` реалізує `ICollection<T>`, `ISet<T>` та `IReadOnlySet<T>` і використовує хеш-таблицю. Така структура забезпечує унікальність елементів і в середньому O(1) для Add/Contains/Remove.
Джерело: https://github.com/dotnet/runtime/blob/main/src/libraries/System.Private.CoreLib/src/System/Collections/Generic/HashSet.cs

### Приклад 3 — комбіноване використання: Dapper SqlMapper
У `SqlMapper.cs` Dapper використовується `HashSet<string>` для відстеження вже оброблених імен параметрів (`consumed`), а параметри зберігаються та шукаються за ключем у словнику. HashSet забезпечує швидку перевірку повторів, Dictionary — доступ до параметра за іменем.
Джерело: https://github.com/DapperLib/Dapper/blob/main/Dapper/SqlMapper.cs

## 3. Порівняльна таблиця складності

| Операція | List<T> | Dictionary<TKey,TValue> | HashSet<T> | Коли використовувати |
|---|---:|---:|---:|---|
| Додавання | O(1) амортизовано в кінець | O(1) середнє | O(1) середнє | List — послідовність; Dictionary — пари ключ/значення; HashSet — унікальні елементи |
| Пошук за значенням | O(n) | O(n) без ключа | O(1) середнє | HashSet для перевірки належності |
| Пошук за ключем | N/A | O(1) середнє | N/A | Dictionary |
| Видалення | O(n) за значенням/індексом | O(1) середнє за ключем | O(1) середнє | Залежить від способу адресації |
| Перевірка наявності | O(n) | O(1) середнє за ключем | O(1) середнє | Dictionary/HashSet для частих перевірок |

*Для хеш-колекцій у найгіршому випадку можливе O(n), наприклад через багато колізій; наведено середню очікувану складність.*

## 4. Реалізовані сценарії
- `FileMetadataCache` зберігає `FileMetadata` за шляхом, використовуючи `StringComparer.OrdinalIgnoreCase`.
- `TagManager` зберігає теги кожної статті в HashSet, тому дублікати не додаються; `UnionWith` та `IntersectWith` реалізують об'єднання та перетин.
- `SearchIndex` будує відповідність «слово → множина ID документів». `SearchMultiple` знаходить документи, які містять усі задані слова.

## 5. Висновки
Dictionary доцільний, коли потрібен доступ за унікальним ключем. HashSet оптимальний для зберігання унікальних значень і перевірки належності. Під час використання важливо коректно визначати рівність і хешування, особливо для власних типів; для рядків можна задавати comparer, наприклад `StringComparer.OrdinalIgnoreCase`.
