# Самостійна робота №14

## Тема
Реалізація exponential backoff.

## Мета роботи
Розробити власний допоміжний клас RetryPolicy для реалізації патерну Retry з експоненційною затримкою та випадковим jitter.

## Використані технології
- C#
- .NET Console Application
- System
- System.Threading

## Опис реалізації

Було створено клас `RetryPolicy`, який забезпечує повторне виконання операцій у разі виникнення тимчасових помилок.

Клас містить три основні параметри:
- `maxRetries` — максимальна кількість повторних спроб.
- `initialDelay` — початкова затримка.
- `jitterFactor` — коефіцієнт випадкового відхилення затримки.

Метод `Execute<T>` приймає операцію типу `Func<T>` та необов'язковий делегат `shouldRetry`.

Для обчислення затримки використовується формула:

`delay = initialDelay * Math.Pow(2, retryAttempt) * (1 + random.NextDouble() * jitterFactor * 2 - jitterFactor)`

## Результати тестування

1. У першому сценарії операція спочатку завершується двома помилками, а на третій спробі виконується успішно.
2. У другому сценарії операція постійно генерує виняток. Після вичерпання повторних спроб виняток передається користувачу.
3. У третьому сценарії перевіряється робота делегата `shouldRetry`, який забороняє повторення для певних типів помилок.

## Висновок

Під час виконання самостійної роботи було реалізовано власний механізм повторних спроб із використанням експоненційної затримки та випадкового jitter.

Експоненційний backoff дозволяє поступово збільшувати час між повторними запитами, зменшуючи навантаження на сервер або іншу систему. Jitter допомагає уникнути одночасного повторення запитів багатьма клієнтами.

Патерн Retry доцільно використовувати для тимчасових помилок мережі, короткочасної недоступності сервера та перевантаження служб.

Не слід застосовувати повторення для постійних помилок, некоректних даних або операцій, які можуть повторно виконатися з небажаними наслідками. Для безпечного використання потрібно передбачати обмеження кількості спроб та перевірку типу винятку.

## Контрольні запитання

**1. Чому експоненційна затримка ефективніша за фіксовану?**

Тому що час між спробами поступово збільшується. Це зменшує навантаження на систему, яка тимчасово не працює.

**2. Для чого потрібен jitter?**

Jitter додає випадкове відхилення до затримки. Він допомагає уникнути одночасних повторних запитів від багатьох клієнтів.

**3. Яку роль відіграє shouldRetry?**

Цей делегат визначає, чи потрібно повторювати операцію після конкретного винятку. Він дозволяє повторювати лише ті помилки, які можуть бути тимчасовими.

**4. Коли повторна спроба не є безпечною?**

Коли операція вже могла виконатися, але відповідь не надійшла, і повторення може призвести до дублювання платежу або іншої небажаної дії. Також повторювати не потрібно постійні помилки та помилки введення даних.
