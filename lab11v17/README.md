### 1. Мета роботи

Ознайомитися з принципами використання абстрактних класів і шаблонного методу (Template Method) у мові програмування C#. Навчитися створювати ієрархію класів, реалізовувати абстрактні та віртуальні методи, застосовувати поліморфізм і організовувати послідовність виконання операцій.

### 2. Постановка завдання

Реалізувати абстрактний базовий клас AuthenticationService для системи автентифікації користувачів.

Шаблонний метод Authenticate() повинен виконувати послідовність операцій:

1. ValidateInput — перевірка введених даних.
2. CheckCredentials — перевірка облікових даних.
3. GenerateToken — створення токена автентифікації.
4. LogAccess — запис інформації про спробу входу.

Необхідно створити три похідні класи: PasswordAuth, OAuth2Auth і BiometricAuth. Кожен клас повинен реалізовувати абстрактні методи відповідно до способу автентифікації. Також необхідно продемонструвати роботу програми, використовуючи список об’єктів базового класу.

### 3. Теоретичні відомості

Абстрактний клас — це клас, який призначений для використання як базовий клас і може містити абстрактні та звичайні методи. Абстрактні методи не мають реалізації в базовому класі та повинні бути перевизначені в похідних класах.

Шаблонний метод (Template Method) — це поведінковий шаблон проєктування, який визначає загальну послідовність виконання алгоритму, залишаючи окремі кроки для реалізації в похідних класах.

Віртуальні методи дають змогу змінювати поведінку базового класу в похідних класах за допомогою перевизначення.

Поліморфізм дозволяє працювати з різними об’єктами через спільний базовий тип, водночас кожен об’єкт виконує власну реалізацію відповідних методів.

### 4. Хід роботи

#### 4.1. Створення базового класу AuthenticationService

Було спроєктовано абстрактний клас AuthenticationService, який визначає загальний алгоритм автентифікації користувача.

Клас містить властивості для зберігання імені користувача, стану автентифікації, поточного статусу обробки та токена.

Шаблонний метод Authenticate() організовує виконання всіх етапів перевірки. У разі помилки автентифікація припиняється, а користувач отримує відповідне повідомлення.

#### 4.2. Реалізація методів обробки

У базовому класі передбачено три абстрактні методи:

- ValidateInput — перевіряє правильність і повноту вхідних даних.
- CheckCredentials — перевіряє облікові дані користувача.
- GenerateToken — створює токен після успішної перевірки.

Метод LogAccess реалізовано як віртуальний. Він відповідає за реєстрацію інформації про спробу автентифікації та може бути перевизначений у похідних класах.

#### 4.3. Створення похідних класів

У програмі реалізовано три способи автентифікації.

**PasswordAuth — автентифікація за паролем.**

Клас перевіряє ім’я користувача та пароль. Для демонстрації використовується тестове значення пароля. Після успішної перевірки генерується токен, а інформація про спробу входу виводиться в консоль.

**OAuth2Auth — автентифікація через OAuth2.**

Клас містить дані про користувача, провайдера та токен доступу. У навчальній реалізації перевірка токена імітується порівнянням із тестовим значенням. Після успішної перевірки створюється внутрішній токен.

**BiometricAuth — біометрична автентифікація.**

Клас імітує перевірку біометричних даних, наприклад відбитка пальця або розпізнавання обличчя. Результат перевірки визначається спеціальною властивістю, яка показує, чи збігаються біометричні дані.

Кожен похідний клас має власну реалізацію абстрактних методів, що демонструє гнучкість шаблонного методу.

#### 4.4. Демонстрація поліморфізму

У методі Main було створено список типу AuthenticationService, до якого додано об’єкти всіх трьох похідних класів.

Для кожного об’єкта викликається метод Authenticate(). Незважаючи на використання спільного базового типу, кожен об’єкт виконує власну логіку перевірки облікових даних.

Додатково передбачено приклад невдалої автентифікації за неправильного пароля. Після виконання операцій програма виводить підсумкові статуси обробки для всіх користувачів.

### 5. Результати роботи програми

У результаті виконання програми продемонстровано:

- успішну автентифікацію за паролем;
- успішну автентифікацію через OAuth2;
- успішну біометричну автентифікацію;
- обробку помилки через неправильний пароль;
- створення токена після успішної перевірки;
- реєстрацію спроб автентифікації;
- використання абстрактного класу, перевизначення методів і поліморфізму.

Програма виводить інформацію про кожен етап автентифікації та підсумковий статус кожного користувача.

Було розроблено навчальну модель системи автентифікації з трьома способами перевірки користувача: за паролем, через OAuth2 і за біометричними даними. Загальна послідовність операцій визначається методом Authenticate(), а специфічна логіка кожного способу реалізується в похідних класах.
