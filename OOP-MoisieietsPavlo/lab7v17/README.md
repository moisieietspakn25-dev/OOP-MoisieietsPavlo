# ЗВІТ
## до лабораторної роботи №7
**з дисципліни «Об’єктно-орієнтоване програмування»**

**Тема:** Приховування методів (`new`) та перевизначення (`override`).

**Мета роботи:** Зрозуміти різницю між приховуванням методів за допомогою ключового слова `new` та перевизначенням методів через `virtual` і `override`, а також навчитися правильно використовувати ці механізми в об’єктно-орієнтованому програмуванні.

### 1. Теоретичні відомості

У мові програмування C# для зміни поведінки методів базового класу використовуються механізми перевизначення та приховування методів.

**Перевизначення методу (`override`)** дозволяє змінити реалізацію віртуального методу базового класу в похідному класі. Воно забезпечує поліморфізм, завдяки якому викликається метод відповідно до реального типу об’єкта.

**Приховування методу (`new`)** дозволяє створити в похідному класі метод з таким самим ім’ям, як у базового класу. При цьому метод базового класу не змінюється. Вибір методу залежить від типу посилання, через яке здійснюється виклик.

### 2. Хід роботи

Під час виконання лабораторної роботи було розглянуто створення консольного застосунку мовою C# та реалізацію ієрархії класів відповідно до індивідуального варіанта №17.

Було передбачено використання базового класу та двох похідних класів для демонстрації відмінностей між перевизначенням і приховуванням методів.

### 3. Опис реалізованих класів

**Клас Calculator**

Базовий клас, який представляє звичайний калькулятор. Він містить віртуальний метод Calculate(), призначений для виконання обчислень із двома числовими параметрами.

**Клас ScientificCalculator**

Похідний клас, який представляє науковий калькулятор. Він перевизначає метод Calculate() за допомогою ключового слова `override`. Це дає змогу продемонструвати поліморфізм і викликати реалізацію похідного класу навіть через посилання базового типу.

**Клас BasicCalculator**

Похідний клас, який представляє базовий калькулятор. Він приховує метод Calculate() за допомогою ключового слова `new`. У цьому випадку виклик методу через посилання базового типу використовує реалізацію базового класу, а через посилання похідного типу — реалізацію BasicCalculator.

### 4. Результати роботи

Під час демонстрації роботи програми розглядаються такі випадки:

- Створення об’єктів базового та похідних класів.
- Виклик методу Calculate() через посилання базового класу.
- Виклик методу Calculate() через посилання похідних класів.
- Порівняння поведінки класу ScientificCalculator, який використовує `override`, та класу BasicCalculator, який використовує `new`.

Результати демонструють, що `override` забезпечує поліморфізм, а `new` приховує метод базового класу без перевизначення його поведінки.

**Примітка:** До остаточного звіту необхідно додати справжній знімок консолі після запуску програми.

### 5. Відповіді на контрольні запитання

**1. У чому полягає різниця між override та new при роботі з методами?**

`override` змінює реалізацію віртуального методу базового класу та забезпечує поліморфізм. `new` приховує метод базового класу, створюючи окрему реалізацію в похідному класі.

**2. Що таке поліморфізм і як override його забезпечує?**

Поліморфізм — це можливість використовувати об’єкти різних класів через спільний базовий тип. `override` забезпечує виклик методу відповідно до реального типу об’єкта, а не лише типу посилання.

**3. Чому при використанні new не відбувається динамічного зв’язування?**

Тому що `new` не перевизначає віртуальний метод, а приховує його. Вибір реалізації прихованого методу залежить від типу посилання, через яке здійснюється виклик.

**4. Коли доцільно використовувати new замість override?**

Ключове слово `new` доцільно використовувати тоді, коли потрібно свідомо приховати метод базового класу, не змінюючи його поведінку. Такий підхід застосовується рідко, коли це виправдано логікою програми.

**5. Що станеться, якщо забути вказати new при приховуванні методу?**

Компілятор C# зазвичай видасть попередження про те, що метод похідного класу приховує успадкований метод. Програма може скомпілюватися, але для явного позначення наміру приховати метод рекомендується використовувати `new`.
