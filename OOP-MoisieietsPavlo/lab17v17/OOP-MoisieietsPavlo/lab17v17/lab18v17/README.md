# Лабораторна робота №18
## Власні винятки та патерн Result

**Студент:** Мойсєєць Павло Андрійович  
**Група:** КН-3/1  
**Варіант:** 17  
**Сценарій:** Обробка конфігурації.

### Мета роботи

Навчитися створювати власні типи винятків та використовувати узагальнений патерн Result для контрольованої обробки помилок.

### Реалізовані компоненти

1. `ConfigurationLoadException` — власний виняток для помилок завантаження конфігурації.
2. `Result<T>` — узагальнений клас для зберігання результату операції або інформації про помилку.
3. `ConfigurationService` — клас для роботи з налаштуваннями.

### Реалізовані методи

- `LoadSetting(string key)` — завантажує налаштування та викидає ConfigurationLoadException, якщо конфігураційний файл відсутній.
- `SaveSetting(string key, string value)` — зберігає налаштування та повертає Result<bool>.
- `Success()` — створює успішний результат.
- `Failure(string error)` — створює результат із повідомленням про помилку.
- `Failure(Exception ex)` — перетворює виняток на результат із помилкою.

### Запуск

```bash
dotnet restore
dotnet build
dotnet run
```

### Висновок

Під час виконання лабораторної роботи було створено власний виняток ConfigurationLoadException для обробки критичної помилки відсутності конфігураційного файлу. Також реалізовано узагальнений клас Result<T>, який дає змогу повертати інформацію про очікувані помилки без використання винятків. Власні винятки доцільні для неочікуваних ситуацій, а Result<T> — для звичайних сценаріїв невдалої операції, наприклад невалідного ключа налаштування.
