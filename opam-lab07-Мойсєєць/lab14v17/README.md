# ЗВІТ
## до лабораторної роботи №14
**Дисципліна:** Об’єктно-орієнтоване програмування

**Тема:** Управління платежами

**Варіант:** 17

### 1. Мета роботи

Ознайомитися з узагальненими колекціями мови програмування C#, навчитися використовувати структури даних HashSet, Queue та Stack для організації обліку рахунків, обробки черги платежів і збереження історії платежів із можливістю повернення останньої операції.

### 2. Постановка завдання

Розробити консольний застосунок для управління платежами, який забезпечує:
- зберігання унікальних ідентифікаторів рахунків за допомогою HashSet;
- формування черги платежів для послідовної обробки за допомогою Queue;
- збереження історії оброблених платежів за допомогою Stack;
- додавання рахунків і створення платежів;
- обробку одного або всіх платежів із черги;
- перегляд рахунків, черги та історії платежів;
- повернення останнього обробленого платежу;
- перевірку правильності введених даних.

### 3. Теоретичні відомості

**HashSet** — колекція, яка зберігає лише унікальні елементи. У роботі вона використовується для зберігання ідентифікаторів рахунків. Якщо користувач намагається додати рахунок з ID, який уже існує, повторний елемент не додається.

**Queue** — колекція, що працює за принципом FIFO (First In, First Out), тобто першим обробляється елемент, який був доданий раніше. Вона використовується для організації черги платежів.

**Stack** — колекція, що працює за принципом LIFO (Last In, First Out), тобто останній доданий елемент вилучається першим. У програмі вона зберігає історію оброблених платежів і дозволяє виконати навчальну симуляцію повернення останнього платежу.

Застосування цих колекцій дозволяє ефективно організувати роботу з даними та розділити різні етапи обробки платежів.

### 4. Опис реалізації програми

Програму реалізовано мовою C# у вигляді консольного застосунку.

Основні функціональні можливості:

1. **Додавання рахунку.** Користувач вводить ідентифікатор рахунку. Програма перевіряє його коректність та унікальність.
2. **Перегляд рахунків.** Відображаються всі збережені ідентифікатори рахунків і їх загальна кількість.
3. **Створення платежу.** Користувач зазначає ID рахунку, суму та опис платежу. Після перевірки даних платіж додається до черги.
4. **Обробка платежу.** Перший платіж із черги вилучається та додається до історії оброблених платежів.
5. **Масова обробка.** Програма послідовно обробляє всі платежі, які перебувають у черзі.
6. **Перегляд черги.** Відображається список платежів, які очікують на обробку.
7. **Перегляд історії.** Користувач може переглянути оброблені платежі.
8. **Повернення останнього платежу.** Останній запис вилучається з історії за принципом LIFO, після чого програма повідомляє суму повернення.

Для представлення платежу використовується окремий клас, який містить ідентифікатор платежу, ідентифікатор рахунку, суму та опис.

У програмі передбачено перевірку введення числових значень, додатності суми платежу, наявності рахунку та порожніх колекцій.

### 5. Тестування програми

Під час перевірки функціональності передбачено такі тестові сценарії:

| № | Тестова дія | Очікуваний результат |
|---|---|---|
| 1 | Додавання нового рахунку | Рахунок успішно додається |
| 2 | Повторне додавання того самого ID | Дублікат відхиляється |
| 3 | Створення платежу для наявного рахунку | Платіж додається до черги |
| 4 | Створення платежу для неіснуючого рахунку | Виводиться повідомлення про помилку |
| 5 | Обробка кількох платежів | Платежі обробляються в порядку надходження |
| 6 | Перегляд історії | Відображаються оброблені платежі |
| 7 | Повернення останнього платежу | Останній запис вилучається зі стеку |
| 8 | Обробка порожньої черги | Виводиться відповідне повідомлення |
| 9 | Введення від’ємної або нульової суми | Платіж не створюється |

Зазначені сценарії визначають очікувану поведінку програми. Результати фактичного виконання тестів необхідно підтвердити запуском застосунку.

### 6. Результати роботи

У результаті розробки створено консольний застосунок для навчального моделювання управління платежами. Реалізовано зберігання унікальних рахунків, постановку платежів у чергу, послідовну обробку, ведення історії та симуляцію повернення останнього платежу.

Використання різних типів колекцій дозволяє продемонструвати практичне застосування структур даних відповідно до їх призначення.

Слід враховувати, що програма не підключена до банківської системи, не зберігає дані постійно та не виконує реального переказу чи повернення коштів. Повернення реалізовано як навчальну операцію над історією платежів.

### 7. Висновок

Під час виконання лабораторної роботи було розглянуто та застосовано колекції HashSet, Queue і Stack у мові програмування C#.

HashSet забезпечує унікальність ідентифікаторів рахунків, Queue організовує послідовну обробку платежів, а Stack дає змогу зберігати історію та вилучати останній запис для моделювання повернення.

Розроблений застосунок демонструє принципи роботи з колекціями, перевірки введених даних і побудови меню консольної програми. Поставлену навчальну мету досягнуто.
