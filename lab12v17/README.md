# ЗВІТ
## до лабораторної роботи №12

**Дисципліна:** Об’єктно-орієнтоване програмування

**Тема:** Узагальнені інтерфейси та реалізація шаблону Repository з використанням модульного тестування.

**Варіант:** 17

**Виконав:** Мойсєєць Павло Андрійович

### 1. Мета роботи

Ознайомитися з узагальненими інтерфейсами та класами в C#, навчитися реалізовувати шаблон Repository для зберігання даних у пам’яті, виконувати CRUD-операції та перевіряти правильність роботи програмного забезпечення за допомогою модульних тестів xUnit.

### 2. Постановка завдання

Необхідно створити окремі проєкти для основної програми та автоматизованого тестування. Реалізувати інтерфейс сутності IEntity, узагальнений інтерфейс IRepository<T> і клас InMemoryRepository<T>.

Відповідно до варіанта 17, потрібно створити сутність Comment із властивостями Text, AuthorName і PostId. Сутність повинна мати унікальний ідентифікатор Id.

Необхідно реалізувати операції додавання, отримання, перегляду, оновлення та видалення записів, а також перевірити правильність їх виконання за допомогою тестів.

### 3. Використані технології

- Мова програмування C#.
- Платформа .NET.
- Середовище розробки Visual Studio Code.
- Система модульного тестування xUnit.
- Колекція List<T> для зберігання об’єктів у пам’яті.
- Узагальнені типи та інтерфейси.

### 4. Опис реалізації

Для організації структури програми створено інтерфейс IEntity, який визначає ідентифікатор сутності. Інтерфейс IRepository<T> описує основні операції керування даними та обмежує тип T сутностями, які реалізують IEntity.

Клас InMemoryRepository<T> реалізує операції керування записами у внутрішній колекції. Передбачено перевірку унікальності ідентифікаторів, пошук елементів за ID та обробку ситуацій, коли необхідний запис відсутній.

Клас Comment представляє коментар до публікації та містить ідентифікатор, текст коментаря, ім’я автора й ідентифікатор публікації.

Для автоматизованого тестування створено окремий проєкт xUnit. Тести перевіряють додавання записів, отримання за ідентифікатором, отримання всіх записів, оновлення та видалення. Також перевіряються помилкові ситуації: повторне додавання ідентифікатора та звернення до неіснуючих записів.

### 5. Результати тестування

Під час тестування перевіряються такі сценарії:

1. Успішне додавання нового коментаря.
2. Відхилення додавання коментаря з повторним ID.
3. Отримання коментаря за його ідентифікатором.
4. Обробка запиту на отримання неіснуючого коментаря.
5. Отримання всіх доданих коментарів.
6. Успішне оновлення наявного коментаря.
7. Обробка спроби оновити неіснуючий коментар.
8. Успішне видалення коментаря.
9. Обробка спроби видалити неіснуючий коментар.
10. Перевірка незмінності раніше отриманого знімка колекції після додавання нового запису.

Фактичні результати тестування необхідно підтвердити запуском команди `dotnet test`. У разі успішного виконання всі тести повинні завершитися без помилок.

### 6. Висновок

Під час виконання лабораторної роботи було розглянуто використання узагальнених інтерфейсів і класів у мові C#. Реалізовано шаблон Repository для роботи з колекцією об’єктів у пам’яті та створено сутність Comment відповідно до індивідуального варіанта.

Реалізація забезпечує виконання основних CRUD-операцій і контроль помилкових ситуацій. Автоматизоване тестування за допомогою xUnit дозволяє перевірити коректність роботи репозиторію та спростити виявлення помилок під час подальшої розробки.

Мету лабораторної роботи досягнуто після успішного виконання та перевірки всіх тестів.
